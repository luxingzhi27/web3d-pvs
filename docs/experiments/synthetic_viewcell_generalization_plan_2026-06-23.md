# 合成 View Cell 数据与泛化训练待办

日期：2026-06-23

## 目的

本文记录一个待实现的泛化性实验方案：构建程序化合成场景，按 NeuralPVS 式 view cell 潜在可见集语义采样，用于预训练和验证当前神经实例剔除模型是否学习到通用遮挡规律，而不是记住某一个真实场景的相机位置、实例编号或固定邻接关系。

这里的合成数据不用于替代真实 `hkust-v3` 和 `ifcbench_fantasy_metropolis_instanced_v2` 数据，而是用于补充跨场景遮挡先验。目标是让模型在新场景中仍能利用离线实例几何、实例上下文、遮挡代理和当前视角查询，输出实例级可见性分数与资源调度优先级。

## 核心问题

当前模型的泛化风险主要来自三类场景依赖：

1. 相机位置分布依赖：如果模型隐式记住某个场景中常见 camera pose，则换场景后失效。
2. 实例关系依赖：如果遮挡代理只记住某个真实场景里的固定遮挡邻居，则无法迁移到新场景。
3. 资产粒度依赖：真实 GLB 拆分方式不同会影响下载优先级监督，模型需要学习资源效用和实例可见性的关系，而不是某个场景的 GLB id。

合成数据要解决的是第二类和第三类问题：让模型反复看到不同尺度、密度、层级、遮挡深度和资源打包方式下的可见性规律。

## 合成场景生成

合成场景应是可控的程序化遮挡关系数据集，不追求真实纹理或视觉美观。每个场景至少包含以下区域类型：

| 区域类型 | 目的 |
|---|---|
| 街区道路 | 模拟长距离视线、两侧建筑遮挡和远近层叠 |
| 楼间缝隙 | 生成强遮挡和窄视锥候选集合 |
| 开阔广场 | 生成弱遮挡、大候选和大可见集合场景 |
| 转角/内院 | 测试少量近处遮挡物对远处可见集合的影响 |
| 密集立面 | 生成大量小实例，测试 false positive 和调度优先级 |
| 高低错落区域 | 覆盖近处低遮挡物、远处大建筑和俯视视角 |

每个合成场景采用层级结构：

```text
场景
  区域 / 街区
    建筑或结构组
      立面 / 楼层 / 遮挡组
        实例构件
```

每个实例需要输出以下离线资源：

| 字段 | 用途 |
|---|---|
| 几何形状 | 盒、薄板、柱体、L 形组合体、重复栏杆等 |
| 世界 AABB | 候选生成、遮挡证据构建和前端粗剔除模拟 |
| 实例点云 | 输入离线点云编码器，生成视角无关实例特征 |
| 层级父节点 | 支持上下文编码和层级遮挡关系分析 |
| 资源包 id | 模拟 GLB 下载、解码和缓存调度 |
| 模拟字节成本 | 训练资源优先级和预算感知排序 |
| 屏幕重要性权重 | 用于 weighted recall、视觉效用和 GLB utility |

## View Cell 采样语义

合成数据必须和真实采样保持同一语义。每个训练样本是一整个 view cell，而不是单个瞬时相机姿态。

采样流程：

1. 生成代表模型查询相机，垂直 FOV 使用 `66°`。
2. 以代表相机为中心定义 view cell 空间范围。
3. 在该 view cell 内随机采样 `K` 个子视点，首版保持同一朝向。
4. 对每个子视点渲染实例 color-id。
5. 对同一个 view cell 内所有子视点的可见实例取并集，得到潜在可见集。
6. 对每个实例记录最大屏幕占比、出现频率和最大可见像素数。
7. 用代表模型查询相机的 `66°` 扩展视锥生成完整候选集，并强制并入潜在可见集。

输出格式应直接对齐当前 viewcell-level PoseCSR：

```text
poses.bin
mvp.bin
visible_offsets.bin
visible_ids.bin
visible_weights.bin
candidate_offsets.bin
candidate_ids.bin
frustum_offsets.bin
frustum_ids.bin
dataset_meta.json
```

`visible_weights` 在合成数据中优先使用最大屏幕占比或 parts-per-million 像素覆盖率。`dataset_meta.json` 必须写清 `K`、view cell 尺寸、是否有朝向扰动、合成场景生成参数和资源包成本分布。

## 与遮挡代理的关系

合成数据与当前方向遮挡代理模型不冲突，但不能把固定邻居编号作为监督。

当前遮挡代理的合理叙事应是：离线编码器从实例点云、场景层级和局部遮挡证据中学习一个视角无关的遮挡表征；运行时用当前相机到实例的视线方向查询这个表征，得到轻量遮挡修正。合成数据可以增强这一叙事，因为它提供了大量不同几何布局下的遮挡关系。

需要避免的做法：

- 不把“某个固定实例 id 是遮挡邻居”作为跨场景监督。
- 不让合成场景使用全局 camera hash 或 raw camera xyz 作为主要输入。
- 不把资源包是否可下载简单等同于“包内是否有任意可见实例”。

推荐做法：

- 对每个合成场景离线构建实例层级和空间关系。
- 用方向扇区、深度顺序、屏幕重叠、父子层级生成弱遮挡证据。
- 遮挡代理只通过最终可见性、方向遮挡证据、可见权重和资源调度损失间接学习。
- 新真实场景只需重新离线提取实例特征和遮挡代理特征，前端仍使用同一个轻量查询头。

## 训练方案

第一阶段：合成预训练。

输入是多个程序化合成场景的 viewcell CSR。训练目标包括实例可见性、可见权重、遮挡代理证据、预测预算约束和资源调度优先级。此阶段的目标不是得到最终真实场景最高分，而是学习通用几何遮挡先验。

第二阶段：真实场景微调。

使用 `hkust-v3` 和 `ifcbench_fantasy_metropolis_instanced_v2` 的真实 viewcell CSR 微调。可以先冻结离线点云编码器，只训练轻量查询头和输出头，再解冻部分上下文/遮挡代理头做小学习率微调。

第三阶段：混合训练。

将合成场景和真实场景按 batch 混合。合成数据提供遮挡形态多样性，真实数据提供资产划分、实例尺度和实际前端调度分布。混合比例初值可设为真实 : 合成 = `1 : 1`，后续扫描 `2 : 1` 和 `1 : 2`。

第四阶段：跨场景留一验证。

使用 leave-one-scene-out 验证泛化：

| 训练集 | 测试集 |
|---|---|
| 合成 + HKUST | IFCBench Metropolis |
| 合成 + IFCBench Metropolis | HKUST |
| HKUST | IFCBench Metropolis |
| IFCBench Metropolis | HKUST |

如果合成预训练有效，应在留一测试中提升 weighted recall、降低 bad cull，并在满足安全召回时保持或提升 useful cull。

## 评估指标

必须同时报告画面安全、剔除效率、资源效率和运行成本。

| 指标 | 含义 |
|---|---|
| pose recall | 每个 view cell 内真实可见实例被找回的比例，再对 view cell 平均 |
| weighted recall | 按屏幕权重统计重要可见实例被找回的比例 |
| bad cull | 错误剔除的真实可见实例占候选集合比例 |
| useful cull | 正确剔除的不可见候选占候选集合比例 |
| avg pred / avg candidate | 预测集合规模和候选集合规模关系 |
| GLB count / byte reduction | 下载资源数量和字节削减 |
| budgeted GLB utility recall | 预算内下载队列覆盖了多少可见效用 |
| image PER / miss pixel rate | 漏预测造成的画面损失 |
| frontend latency | 前端候选生成、WebGPU 推理、调度和渲染过滤耗时 |

普通 precision、F1 和 instance accuracy 需要保留，但不能单独作为主结论。

## 风险

合成数据可能和真实资产分布不一致，导致模型学到过于规则的盒体遮挡关系。第一版必须主动加入实例粒度随机化、薄片构件、重复小构件、遮挡深度变化和资源包打包噪声。

另一个风险是合成数据规模过大但几何分布单一。数据生成器应优先保证遮挡模式多样性，而不是只增加场景数量。

如果合成预训练只能提升单场景 F1，却不能改善 leave-one-scene-out 的安全召回、bad cull 或图像损失，则该方案不能作为泛化性主论据，只能作为辅助消融。
