# PVS 主线核心消融补全计划

日期：2026-08-23  
状态：执行中

## 目标

当前正式矩阵已经评价分层关系先验、视点区域矩包络、加权召回保护和表征对比，但“去除分层关系先验”仍保留几何生成的 28 维生存场，无法证明生存场整体是否有效。当前表征对比还表现出稳定负面作用，因此后续完整模型固定移除表征对比，只保留逐视点平衡分类、加权召回保护和困难边界分数间隔。

本轮只补论文核心创新所需的消融，不重新扫描超参数，不增加逐实例校准消融，也不建立大规模组合矩阵。

## 固定完整模型

完整模型固定为：

- 分层遮挡关系先验和逐实例校准生存场；
- 视点区域矩包络频谱查询；
- 逐视点平衡分类、加权召回保护和困难边界分数间隔；
- 表征对比关闭，尾部分离全部由 logit 间隔承担；
- 视觉效用、下载、GLB 字节和前端资源目标继续关闭。

已有 `without_contrastive_separation` 三种子成员就是上述配置，均完成 `40 epoch × 900 step`。执行前先验证其 checkpoint、训练配置、split 和 calibration 结果，验证通过后作为只读完整模型参考，不无理由重复训练，也不改写原输出名称。

## 正式消融成员

| 成员 | 保留内容 | 去除或替换内容 | 主要回答的问题 |
|---|---|---|---|
| 完整模型 | 全部分层生存场、矩包络和最终损失 | 表征对比已固定关闭 | 统一比较参考 |
| 去除分层关系 | 几何生存场、逐实例校准、矩包络和最终损失 | 分层关系编码改为同容量几何编码 | 真实遮挡关系是否优于实例自身几何 |
| 去除生存场 | 几何与矩包络查询 | 删除每实例 28 维场、方向生存查询和全部生存场辅助损失 | 生存场整体是否改善可见性预测 |
| 通用 28 维对照 | 与生存场相同的每实例资产宽度、轻量方向混合和查询输出宽度 | 28 维改为随机初始化的可训练无结构表示；取消 Logistic 生存语义、深度单调约束、深度删失和关系监督 | 收益来自遮挡生存结构，还是仅来自额外实例记忆容量 |
| 去除视点区域矩包络 | 分层生存场和最终损失 | 区域查询改为中心视点查询 | 视点区域积分是否优于单点视角查询 |
| 去除加权召回保护 | 完整架构、逐视点平衡分类和困难边界间隔 | 召回保护权重设为零 | 加权召回安全项是否保护重要可见实例 |
| 去除困难边界分离 | 完整架构、逐视点平衡分类和加权召回保护 | 尾部分离权重设为零 | 困难正负边界优化是否提高 precision、specificity 和 balanced accuracy |

不新增以下成员：

- 不做“分层生存场无逐实例校准”；
- 不做冻结随机 28 维，因为它只能评价噪声输入，不能作为同学习容量对照；
- 不做单独移除表征对比，已有三种子结果已经证明当前实现有负面作用；
- 不做普通 BCE、完整 RVL、不同尾部比例等扩展损失矩阵。

## 实现要求

### 生存表示模式

主模型增加三个互斥模式，保持同一训练和评价入口：

1. `生存场`：保持当前 28 维单调生存场和离线关系编码路径；
2. `通用 28 维`：每实例保存 28 个可训练参数，只接受最终可见性标签梯度；使用与生存场相同规模的共享方向混合和相同输出宽度，但不解释为生存概率，不读取关系图和深度剥离监督；导出后仍是固定半精度表，前端不增加在线邻居查询；
3. `无生存场`：不创建、读取或导出 28 维表，不计算生存语义和关系条件；最终查询头按缩减后的输入维度构造。

训练器必须根据模式自动处理损失：

- `生存场` 保留深度删失损失、关系一致性和逐实例校准正则；
- `通用 28 维` 和 `无生存场` 的上述三项必须为零，并且不得暗中读取关系监督；
- 三种模式均使用相同的可见性标签、候选和视点区域输入。

导出文件需要记录表示模式、每实例维数、实际特征表字节和查询输入维数。通用 28 维与完整生存场应具有相同的实例表宽度；无生存场应体现真实资产缩减。

### 最终损失

所有成员共同关闭训练期表征对比投影头。完整损失固定为：

```text
逐视点平衡分类
+ 0.30 × 加权召回保护
+ 0.20 × 渐入后的困难边界 logit 间隔
```

其余参数沿用正式 `s02`：学习率 `2e-4`、边界间隔 `0.50`、前 15% 更新渐入、每批 4 个 pose。去除加权召回保护时只把 `0.30` 改为零；去除困难边界分离时只把 `0.20` 改为零，禁止同时改变学习率、样本挖掘比例或阈值协议。

## 代码与测试步骤

1. 在 `pvs_model.py` 中实现三种生存表示模式，并保证完整生存场路径数值不变。
2. 在 `train_pvs.py` 中按模式关闭不适用的监督，删除表征对比投影头在本轮 runner 中的启用路径。
3. 在 `export_pvs.py` 中导出对应运行表和元数据，补充无生存场及通用 28 维的 schema 检查。
4. 在 `run_pvs.py` 中增加简短稳定的 `core-ablation` 入口，输出统一放在：
   - `neural_instance_culling/model/out/pvs_mainline_core_ablation/`
   - `neural_instance_culling/benchmark/out/pvs_mainline_core_ablation/`
5. 单元测试覆盖表示模式互斥、无生存场不读取关系、通用 28 维获得可见性梯度、辅助损失正确归零、导出维度和 checkpoint 重载。
6. 三种表示模式分别执行一次真实 CUDA 单步前向和反向。smoke 只检查代码契约，不作为是否启动正式训练的门控。

## 正式训练调度

固定数据集为 `pose_csr_hkust_v3_main_stratified_calibration_fov66_v1`，split 数量继续为 `5926/659/730/684`。候选、GT、可见权重、FOV 和关系监督来源均不改变。

- 需要新训练的成员：六种消融，每种三个种子，共 18 个成员；
- 种子：`20260801`、`20260802`、`20260803`；
- 每成员：从头训练 `40 epoch × 900 step`；
- batch：每批 4 个 pose；
- checkpoint：每 4 epoch 保存和评价；
- calibration：每个 checkpoint 独立冻结阈值，正式 bootstrap 为 10,000 次；
- test：训练、阈值和 validation 比较期间保持未读取；
- 日志：每个成员独立保存 stdout、stderr、训练历史和 calibration 摘要。

四张 GPU 各运行一个训练进程，采用完成即补位的队列调度。三个种子和六个变体均必须完成；中间指标不能取消后续成员，只有非有限数值、CUDA OOM 或硬件故障允许暂停，修复后从未完成成员继续。

## 汇总与比较

所有比较使用相同的 730 个 validation pose，并按种子聚类、种子内 pose 重采样执行 10,000 次 paired bootstrap。核心差值为：

- 完整模型减去无生存场：生存场整体贡献；
- 完整模型减去通用 28 维：生存语义和遮挡监督相对同容量实例记忆的贡献；
- 通用 28 维减去无生存场：额外 28 维容量本身的贡献；
- 完整模型减去无分层关系：分层遮挡关系贡献；
- 完整模型减去无矩包络：视点区域频谱贡献；
- 完整模型减去无召回保护：加权召回保护贡献；
- 完整模型减去无困难边界：困难边界分离贡献。

每个成员必须报告 weighted recall 及其下界、pose/aggregate precision、recall、accuracy、balanced accuracy、specificity、useful cull、bad cull、平均预测数、GLB 数量和字节、特征表大小与 CUDA 延迟。能够导出运行资产的三个生存表示模式还需执行浏览器数值 parity；硬件 WebGPU 延迟只有 adapter 通过 NVIDIA/Vulkan 门时才能报告。图像 Color-ID 评价使用现有硬件缓存和同一 validation pose，不补 GT。

最终报告明确区分：生存场是否有效、结构化生存场是否优于同容量实例记忆、分层关系是否有效，以及两项核心损失分别改善安全性还是分类边界。正式评价完成前不修改默认 checkpoint、阈值或前端资产。
