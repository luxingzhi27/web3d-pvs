# 当前可见性模型与训练流水线

更新时间：2026-08-10

本文描述当前方向遮挡代理模型、训练数据、阈值校准和前端导出。训练端可以使用较重的点云和关系编码；浏览器只消费固定特征表和轻量相机查询头。

## 1. 输入与输出

一个训练 pose 包含后退 `66°` 相机、候选实例集合、实例 AABB、所属 GLB、真实可见标签、可见权重和离线遮挡证据。模型对每个候选实例输出：

- 可见性分数，用于形成实例级预测集合；
- 视觉效用分数，用于衡量实例对当前画面的价值；
- GLB 下载优先级，用于请求、解码和缓存排序。

三个输出头共享实例查询特征，但显示粒度和下载粒度保持分离：一个 GLB 中只有部分实例可见时，前端只能显示这些实例。

## 2. 视角无关的离线特征

### 几何特征

当前编码器是 PointNet++ 风格的实例点云编码器。输入来自离线 GLB 表面点缓存和实例 AABB 属性，不读取相机。每个实例最多使用 64 个采样点；模型稳定地选取最多 24 个中心，每个中心选择最多 12 个近邻。

局部多层感知器处理近邻点与相对中心坐标，在近邻维度同时进行均值和最大池化，再在中心维度进行一次均值/最大池化融合，输出 96 维几何特征。它是项目内可复现的轻量实现，不依赖浏览器端点云编码。

HKUST 的点云缓存按可下载 GLB 原型去重；实例特征生成时通过 `instance_to_glb` 取得对应原型点，再结合实例自己的 AABB 属性，因此共享 GLB 的实例仍保留独立的空间特征语义。导出后的运行表则严格按实例编号排列。

### 方向上下文和遮挡代理

离线遮挡证据按“方向单元、深度层、来源实例”组织。当前默认方向模型使用 8 个方向、3 个深度层，每个单元最多保留 8 个来源。来源不是简单的固定最近邻，而是由同一投影几何中可能提供遮挡证据的实例筛选得到。

关系编码器把目标/来源几何、相对位置、尺寸比、距离和证据强度组成边特征，再经过边多层感知器和证据加权池化，生成：

- 64 维上下文特征，描述实例周围的离线关系；
- 192 维方向遮挡代理，按 8×3 个方向/深度单元保存。

运行特征布局为：

```text
96 维几何 + 64 维上下文 + 192 维方向遮挡代理 = 352 维
```

方向代理不是 dynamic-pool 的 teacher，也不是前端在线邻居查询。训练时的证据来自离线投影几何和 GT 标签，浏览器只读取导出的固定表。

## 3. 相机查询头

运行时对每个候选实例计算当前相机到实例中心的单位视线方向和轻量射线空间量，包括归一化距离、视线夹角、屏幕相对位置和角尺度。相机世界坐标不是主要记忆输入，当前正式资产也不使用 camera hash。

查询头用视线方向对 8×3 个代理单元进行门控，得到 8 维当前方向代理，再将其与 96 维几何和 64 维上下文拼接形成 168 维查询特征。可见性头结合查询特征、射线特征及其交互输出可见性分数；视觉效用头和 GLB 优先级头复用同一查询表征。

浏览器运行 schema 为 `directional-occlusion-proxy-scheduler-v1`。当前前端固定特征、模型权重和 AABB 都是 FP16/紧凑二进制布局，运行时不执行 PointNet++、Graph U-Net、Triplane、dynamic-pool、动态图传播或完整 AABB 投影特征提取。

## 4. 损失组成

当前主线使用 `rvl_strong_v2` 语义，并在可见性集合损失中同时处理：

- 带可见权重和漏检惩罚的 BCE；
- Tversky 集合损失，保护重要可见实例；
- pose 内可见/不可见排序和困难负样本约束；
- 预测数量预算约束，抑制无边界过预测；
- 视觉效用和 GLB 优先级排序损失；
- 方向遮挡代理的证据、可见保护和稀疏约束；
- RVL 项，对可见漏检和高证据误报施加可解释的集合级权重。

RVL 位于可见性主损失中，不是 dynamic-pool 伪标签。它直接使用 GT 可见标签、离线证据、可见权重和资源成本，让训练目标同时关注重要可见实例和高代价误报。遮挡代理损失只约束遮挡分支是否学习到可解释的方向证据，不能单独代表可见性效果。

当前优化阶段正在比较上下文、遮挡生存场和不同损失组合。安全约束效用损失在最新矩阵中整体弱于 RVL 控制组，暂不进入主线；后续若重新启用，必须使用独立实验目录并按当前优化阶段文档登记。

## 5. 训练、校准和导出

训练前检查：

1. `dataset_meta.json`、pose、可见集合和候选集合存在；
2. 每个 pose 满足 `visible_ids ⊆ candidate_ids`；
3. runtime metadata 的实例数、AABB 和实例到 GLB 映射一致；
4. 点缓存和离线特征的实例/原型映射有明确元数据；
5. 遮挡证据的方向、深度和来源维度与模型配置一致。

训练期间保存 stdout/stderr、逐 epoch 指标、checkpoint 和特征表。阈值只能从本 checkpoint 的 calibration split 选择，test split 不参与选择。

当前统一工作点规则为：

```text
先满足 weighted recall > 0.99；
再要求 weighted recall 的单侧 95% 置信下界 > 0.99；
在合格工作点中比较 precision、F1、useful cull、资源字节和延迟。
```

普通 pose recall、precision、F1、accuracy、balanced accuracy、useful cull、bad cull、平均预测数和 GLB 字节必须全部保留。当前优化阶段暂不使用 bad-cull 置信区间上界否决路线，但 bad cull 仍是画面风险诊断。

导出目录至少包含：

- `instance_model_meta.json`：schema、实例数、输入维度、阈值、FOV 和特征来源；
- `instance_pvs_assets.bin`：前端权重和固定特征；
- 与运行元数据对应的实例 AABB、实例到 GLB 映射和布局信息。

浏览器不需要训练点云、证据源实例列表或 PyTorch checkpoint。

## 6. 当前结果边界

默认前端继续使用 `pvs_directional_occlusion_proxy_encoder_rvl_strong_v2_full40_best`。2026-08-09 的快速候选已被 2026-08-11 修正正式矩阵和 2026-08-12 Fourier 补充矩阵取代，不能再用其分数描述当前模型能力。现有证据支持保留遮挡生存场和 Fourier117 查询作为强参考，但普通上下文聚合尚未证明独立收益。
