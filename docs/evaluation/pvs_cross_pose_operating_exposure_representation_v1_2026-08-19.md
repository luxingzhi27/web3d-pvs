# 跨视点工作边界与区域暴露监督快速评价

- 日期：2026-08-19
- 实验：`pvs_cross_pose_operating_exposure_representation_v1`
- 数据：HKUST v3 validation 全部 pose
- 阈值：每个 checkpoint 仅由各自 calibration split 冻结
- 状态：单种子快速结论，不修改默认模型和前端资产

## 实验目的

本实验在现有 `96` 维几何与 `28` 维逐实例生存场基础上，仅改变训练方法。跨视点工作边界损失尝试让多个 pose 共享一个负例压制边界，并在 weighted recall 达标后停止额外正例奖励；区域暴露监督使用 train-only subpose 命中率约束共享查询表征。两者都不增加浏览器输入、固定表维度或在线查询次数。

D 相对 A 的 aggregate precision 提高 `8.09` 个百分点，ordinary recall 提高 `12.33` 个百分点，weighted recall 提高 `0.205` 个百分点，balanced accuracy 提高 `7.45` 个百分点，F1 提高 `10.51` 个百分点，useful cull 提高 `2.46` 个百分点，平均预测数下降 `14.1%`。D 的 pose precision、pose recall 和 pose balanced accuracy 分别为 `0.3068`、`0.8722` 和 `0.8099`。

B 与 C 单独启用时都过预测，D 组合后才明显改善，说明当前观察到的是强交互，而非两个已经证明的独立增益。D 的训练期共享边界约为 logit `-0.013`，calibration 安全阈值约为 logit `-2.512`，二者仍相差约 `2.50`；当前损失尚未真正把训练边界对齐到部署工作点。

D 的导出资产由 `4,670,088` 字节固定表、`45,198` 字节查询权重、`576` 字节频率和 `32,768` 字节查表组成，总计 `4,748,630` 字节，约 `4.53 MiB`，低于 `7 MiB` 硬上限。训练期暴露辅助头和工作边界未导出，运行时仍对每个 view-cell 做一次批量查询，不增加邻居查询、图传播、subpose、HZB、八角点投影或第二分支。

CUDA 回放只用于同一服务器上的相对诊断。图像级 Color-ID 指标尚未回填，真实移动端 WebGPU 的 `10k` 候选 p95 也尚未执行，因此本报告不把 CUDA 回放解释为移动端性能结论。

## 结论

组合 D 在单种子快速实验中同时提高了 weighted recall 安全门下的 precision、balanced accuracy、useful cull 和 GLB 资源削减，而且没有扩大前端资产或在线计算。单模块 B、C 均失败，当前只能把 D 视为值得进行三种子长训的组合训练候选。正式结论需要三种子从头训练、paired bootstrap、Color-ID 图像评价和硬件 WebGPU/移动端测量；完成前不修改默认 checkpoint、阈值或前端资产。
