# M4 注册输入分支消融矩阵：validation 评价与路线判定

日期：2026-08-02  
阶段：M4 核心输入分支消融  
状态：validation-only 矩阵已完成；路线 B 已冻结；未读取正式 test

## 1. 目的与结论

M4 从头训练五种输入配置，每种配置使用三个固定随机种子，检验几何表征、场景上下文表征、方向遮挡代理以及显式遮挡抑制对当前可见性模型的独立作用。比较严格使用同一 HKUST 空间 validation 数据和后退相机候选集合，阈值由每个成员自己的独立 calibration 冻结，不在 validation 或 test 上重新扫描。

正式路线判定为**路线 B**：`geometry_context_ray` 作为主可见性架构，方向遮挡代理保留在固定场景特征表中作为辅助分支和消融对象，不将其写成已经证明的独立论文贡献。完整模型相对该参考配置的 useful cull 增益为 `-0.002405`，10,000 次分层配对 bootstrap 的 95% 区间为 `[-0.019747, 0.007849]`，没有达到路线 A 预注册的 `+0.02` 且区间下界大于 0 的门槛。完整模型的 bad cull 增量为 `+0.001083`，区间为 `[+0.000332, +0.001818]`，低于预注册的 `+0.002` 上限。

这表示当前证据支持“几何、上下文和视线查询组成更稳定的主系统”，不支持“方向遮挡代理单独带来显著有效剔除收益”。图像损失和下载字节替代门不在 M4 摘要中，不能由本报告推断图像无损或下载收益；后续 M5 视觉安全评价仍然必须独立执行。

## 2. 实验协议

### 2.1 数据和候选语义

| 项目 | 口径 |
|---|---|
| 场景 | HKUST v3 空间隔离数据 |
| 评价 split | validation |
| 每个成员 pose 数 | 664 |
| 成员数 | 5 个变体 × 3 个 seed = 15 |
| 候选集合 | 数据集中严格保存的 66° 后退相机候选 |
| 候选处理 | 不补入真实可见实例、不做 GT union、不截断候选 |
| 相机口径 | 模型和后退候选相机 66°；真实渲染 60° 的约定不改变本次离线 validation 候选 |
| 阈值 | 每个 checkpoint 从独立 calibration 冻结；没有 validation threshold scan |
| test | 未读取；路线文件记录 `testRead=false`，矩阵摘要状态为 validation-only |
| 不确定性 | 10,000 次分层 paired bootstrap，先对 seed 聚类，再在 seed 内对 validation pose 重采样 |

候选哈希和候选数量逐 pose 对齐后才进行比较，因此不同变体的差异不能由候选集合变化解释。bootstrap 使用配对记录：同一 seed、同一 pose 的两个变体共享候选和真实标签，再计算指标差异。

### 2.2 五种输入配置

这里的“几何表征”是离线从实例几何中提取、运行时固定读取的实例特征；“上下文表征”描述实例与场景中其他实例的离线关系；“方向遮挡代理”是由投影几何弱监督得到的、按方向组织的遮挡证据压缩表示；“视线查询”是当前相机到实例的单位视线方向和轻量射线空间标量。显式抑制头是根据这些查询结果额外产生遮挡修正的输出分支。

| 变体 | 运行时可用输入 | 作用 |
|---|---|---|
| `aabb_ray` | AABB 派生的射线/屏幕标量 + 视线查询 | 只保留轻量包围盒几何基线 |
| `geometry_ray` | 几何表征 + 视线查询 | 检验离线实例几何是否超出 AABB 提供信息 |
| `geometry_context_ray` | 几何表征 + 上下文表征 + 视线查询 | M4 的主参考配置 |
| `geometry_context_proxy_ray_no_inhibition` | 几何、上下文、方向遮挡代理和视线查询；显式抑制头关闭 | 区分“代理作为输入”与“显式抑制输出”的作用 |
| `full` | 几何、上下文、方向遮挡代理、视线查询和显式抑制头 | 当前完整注册配置 |

消融通过 checkpoint 中登记的运行时分支屏蔽执行。固定特征文件的布局没有被删除，避免由于资产格式变化引入额外变量；被屏蔽的分支不会参与查询决策，对应辅助监督也按协议关闭。

## 3. 指标定义

以下指标均针对保存的后退相机候选计算。设候选集合为 C，真实可见集合为 G，模型预测集合为 P，则真正例、假正例、假负例和真负例分别为 TP = P ∩ G、FP = P - G、FN = G - P、TN = C - (P ∪ G)。

### 3.1 画面安全指标

- **weighted recall（加权召回率）**：对真实可见实例按 `visible_weights` 加权后，被预测集合找回的比例。它保护高权重构件，但不惩罚 false positive；本项目的权重来自采样证据，不能称为真实像素覆盖率。
- **recall（集合召回率）**：TP / (TP + FN)，表示真实可见实例有多少被找回。它直接反映漏显示风险，但对所有实例等权。
- **bad cull（错误剔除率）**：FN / |C|，表示候选中被模型错误剔除的真实可见实例比例；也同时作为画面风险指标。该指标越低越安全。

### 3.2 剔除效率和诊断指标

- **useful cull（有效剔除率）**：TN / |C|，只统计被正确剔除的不可见候选，不把漏掉的可见实例算成效率。
- **precision（精确率）**：TP / (TP + FP)，预测为可见的实例中真正可见的比例。
- **F1**：precision 与 recall 的调和平均，用于诊断误报和漏报的折中，不能单独决定 PVS 主线。
- **avg predicted count（平均预测数量）**：每个 validation pose 的 (|P|) 再平均，反映前端最终需要保留的实例规模。

本报告表中的 precision、recall、F1、useful cull 和 bad cull 是每个 seed 在 664 个 pose 上合并 TP/FP/FN/TN 后得到的 aggregate 指标；“三 seed 均值”是三个 aggregate 结果的算术平均，不是把三个 seed 的实例计数重新拼接。M4 摘要没有逐 pose 图像渲染，因此 miss pixel rate、wrong-ID pixel rate、图像 PER、GLB 数量削减、GLB 字节削减和前端延迟均标记为未实现，不能从 useful cull 替代推断。

## 5. 主增量比较与路线门控

主增量固定为 `full - geometry_context_ray`。下表是 10,000 次分层配对 bootstrap 的观察差值和 95% 区间；正值表示完整模型更高，负值表示更低。

| 指标 | full - reference | 95% bootstrap 区间 | 解释 |
|---|---:|---:|---|
| useful cull | -0.002405 | [-0.019747, 0.007849] | 没有有效剔除增益 |
| bad cull | +0.001083 | [+0.000332, 0.001818] | 增加但未超过 +0.002 门槛 |
| weighted recall | +0.000105 | [-0.001673, 0.002641] | 安全加权召回没有稳定增益 |
| recall | -0.016228 | [-0.019417, -0.013042] | 普通集合召回下降 |
| precision | -0.023517 | [-0.116370, 0.038490] | 区间跨零，不能宣称稳定变化 |
| F1 | -0.025179 | [-0.110019, 0.033467] | 区间跨零，不能宣称稳定变化 |
| 平均预测数 | +10.59 | [-32.63, 67.51] | 区间跨零 |

路线 A 的预注册条件是 useful cull 平均增益至少 `+0.020000` 且区间下界大于 0，同时 bad-cull 区间上界不超过 `+0.002000`。完整模型只满足后一个条件，故路线 A 不通过。另一个可能用于保留路线 A 的图像/字节替代门没有被纳入本次 M4 summary，因此不能事后调用该门改变判定。

## 6. 主线含义和边界

1. 从 `aabb_ray` 到 `geometry_ray`，三 seed 均值 useful cull 从 `0.931929` 提升到 `0.967759`，平均预测数从 `393.80` 降到 `184.15`；这支持离线几何实例表征具有明显工程价值。
2. 加入上下文后，`geometry_context_ray` 相比 `geometry_ray` 的 useful cull 三 seed 均值几乎不变（`0.967879` 对 `0.967759`），但 weighted recall 略高；当前证据适合把上下文作为主系统的一部分，不能把它描述为已经显著提高所有指标。
3. 方向遮挡代理和显式抑制的完整配置没有显示出预注册的独立 useful-cull 增益，且完整配置的普通 recall 低于参考配置。方向代理继续保留，原因是它仍可能在图像长尾、资源调度或跨区域实验中提供辅助信息，但这些作用必须由 M5/M7 的独立证据验证。
4. `weighted recall` 接近或高于 `0.99` 只说明重要可见权重得到较好保护，不等同于普通实例 recall、图像无损或移动端体验无损。三 seed 中部分成员的 weighted recall 低于 `0.99`，说明 calibration 安全点在 validation 上仍有随机种子差异。
5. 本报告没有测试集指标，也没有把当前路线 B 的 validation 结果写成跨场景泛化结论。正式 test 必须使用冻结 checkpoint、独立 calibration 阈值和一次性 test 评估。
