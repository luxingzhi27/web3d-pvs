# M5 HKUST 图像安全门失败分析

日期：2026-08-02
所属阶段：M5 实例级图像安全
状态：失败原因已定位，未启动修复训练
保留判断：保留为当前模型的失败证据，不作为主线通过结果

## 结论

HKUST validation 的实例级图像评价不是由候选集合或浏览器实例绑定错误造成的。候选集合包含主要漏检构件，实例级 Color-ID 绑定预检通过，参考图像自洽比较的 PER 为 0。错误发生在模型对候选实例输出的可见性分数上：少数高屏幕贡献构件在冻结阈值下得到过低分数，随后被剔除。

完整 validation 的聚合 miss-pixel rate 为 `0.4947%`，但 view-cell 均值为 `0.5409%`、p95 为 `3.1973%`，最大 view-cell 为 `13.1422%`，所以图像安全门仍失败。校准集均值为 `0.2935%`，p95 为 `1.2934%`，说明校准均值不能代表未见空间块中的长尾安全性。

## 根因判断

1. **不是候选生成失败。** row 41 的关键实例都存在于后退 66°候选集合，不能通过扩充候选集合解释。
2. **不是渲染绑定失败。** 浏览器使用实例槽位和组件 ID 绑定，参考渲染自洽 PER 为 0，模型预测集合改变时的错误与实例 ID 一致。
3. **主要是空间留出下的高贡献长尾漏检。** 当前训练的正例重要性来自 color-ID 屏幕覆盖的最大池化权重，并在损失中经过 `log1p` 和上限归一化；多个高权重正例会进入相同的饱和区，不能继续区分 21k 与 73k 的视觉风险。训练还以 view-cell 集合为单位约束预测数量，容易在候选仅 45 个、真实集合 18 个的稀疏区域压低边界实例分数。
4. **普通 weighted recall 不能替代图像安全。** 它是集合内的加权找回率，不能表示一个漏检实例在最终 60°画面中占用了多少像素；因此当前模型同时出现较高 weighted recall 和少数大型构件的高 miss-pixel 是指标语义允许的结果。

## 修复实验准则

下一次模型实验必须使用独立命名和同一空间 split，不能修改当前冻结资产。优先验证以下假设：

- 将可见权重从饱和的 `log1p` 重要性扩展为训练视点中可复现的屏幕占比/最大池化权重，并加入“高贡献正例最低分数”损失，能降低 view-cell p95 miss-pixel，而不把所有候选都预测为可见；
- 将稀疏候选 pose 的正例排名与视觉贡献排序分开，避免数量约束把高贡献构件和低贡献构件一同压低；
- 在 validation/calibration 上冻结阈值和安全门后，再运行完整 image-ID 评价。不得在 test 上扫描阈值，也不得在前端增加隐藏的高贡献实例白名单。

修复实验至少报告普通 precision/recall/F1、weighted recall、useful/bad cull、avg prediction、miss-pixel mean/p95/max 和候选/实例运行延迟。若修复只降低 miss-pixel 却造成候选预算或端侧延迟失控，不能作为主线改进。
